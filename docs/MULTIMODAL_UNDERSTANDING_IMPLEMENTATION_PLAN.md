# PastVideo 多模态视频理解实施计划

> 状态：待评审，不代表功能已经实现
>
> 范围：本地片段描述、OCR、Whisper 语音转录、多模态融合搜索、桌面端与服务端集成、真实 E2E 测试
>
> 原则：本地优先、GPU 优先、增量可用、结果可解释、分析产物可复用

## 1. 目标

在现有视觉语义向量检索之上，让 PastVideo 同时理解：

1. **画面发生了什么**：为带时间范围的视频片段生成简洁、可检索的文字描述。
2. **画面写了什么**：识别字幕、路牌、演示文稿、软件界面和其他可见文字。
3. **视频说了什么**：使用本地 Whisper 生成带时间戳的语音转录。
4. **如何综合检索**：融合视觉、描述、OCR、转录和精确全文匹配，返回统一结果。

用户最终应能通过一句自然语言找到对应时刻，并看到命中依据。例如：

- “有人把红色行李箱放进汽车后备箱”命中视觉和片段描述。
- “屏幕上出现 connection refused”命中 OCR。
- “谁提到了下周发布”命中语音转录。
- “演示 PastVideo 性能时屏幕出现 GPU”同时命中转录、OCR 和视觉描述。

## 2. 当前基础与约束

PastVideo 已经具备：

- 30 秒固定窗口、5 秒重叠的片段级视觉索引。
- 本地 Qwen3-VL Embedding、CUDA 批处理及 NVDEC 优先解码。
- 文本到视频、图片到视频搜索。
- Media → Understanding → Analyzer → Artifact → Index 的可追溯数据模型。
- 不可变 Artifact、多物理索引、索引别名和结构化查询。
- Windows 桌面端、无 GUI 服务端和增量搜索。

本计划必须遵守以下约束：

- 默认不把视频、音频、帧、文字或向量发送到外部服务。
- 不导入不支持的视频后缀，继续明确排除 MTS 和 M2TS。
- 未完成任何有效分析的视频不得作为相应模态的搜索候选。
- 每个视频或分析器完成后立即更新状态和可搜索内容，不等待整批完成。
- 停止任务时保留已经安全提交的结果，后续可断点续跑。
- 不修改真实测试目录中的源视频。
- 避免无界帧缓存、音频缓存和模型并发导致 CPU 内存增长。

本机实施基线：

- GPU：NVIDIA GeForce RTX 4090 D，24 GB 显存。
- 已有本地 Qwen3-VL Embedding 运行环境。
- 已缓存 Qwen3-VL-4B-Instruct，可作为片段描述候选模型。
- Whisper 和 OCR 的具体本地模型在实施第一阶段通过烟雾测试后锁定。

## 3. 交付范围

### 3.1 片段文字描述

新增本地 `scene_caption` 分析器。它复用视觉索引抽取的代表帧，不重复完整解码视频，并输出受约束的结构化记录：

```json
{
  "description": "一个人在停车场把红色行李箱放进汽车后备箱。",
  "setting": "停车场",
  "activities": ["搬运行李"],
  "salient_objects": ["人物", "红色行李箱", "汽车"],
  "camera_motion": "固定镜头"
}
```

初始模型候选为本地 Qwen3-VL-4B-Instruct。提示词和输出 JSON Schema 必须版本化；无法解析的输出重试一次，仍失败则进入该分析器的失败记录，不阻塞 OCR、转录或现有视觉索引。

片段范围第一版与现有 30 秒窗口对齐，以降低整合风险。后续可以引入镜头边界，但不得破坏已有时间范围和 Artifact 可复现性。

### 3.2 OCR

新增本地 `ocr` 分析器，优先采用 PaddleOCR 系列模型，并保留替换其他 OCR 后端的接口。

处理策略：

1. 复用代表帧和时间戳。
2. 增加低成本画面变化检测，避免对高度相似的连续帧重复 OCR。
3. 保存原始文本、标准化文本、置信度、帧时间和边界框。
4. 按标准化文本、空间重叠和时间邻近关系合并重复结果。
5. 中文、英文和数字默认可用；其他语言作为后续扩展。

单条记录示例：

```json
{
  "text": "Connection refused",
  "normalized_text": "connection refused",
  "confidence": 0.96,
  "frame_ms": 18420,
  "box": [[112, 83], [592, 83], [592, 132], [112, 132]]
}
```

### 3.3 Whisper 语音转录

新增本地 `transcript` 分析器，使用 `faster-whisper`：

1. FFmpeg 一次性抽取 16 kHz 单声道音频流。
2. 使用 VAD 跳过静音区间。
3. 自动检测语言，并支持显式指定语言。
4. 保存句段时间戳；条件允许时保存词级时间戳。
5. 保存语言、平均置信信息和模型版本。
6. 无音轨和全静音视频应正常完成，生成空 Artifact，而不是报错。

首选模型由本地实测决定：先比较 `large-v3-turbo` 与较小模型在显存、吞吐和中英文准确率上的表现，再固定桌面默认值。模型必须完全本地运行。

### 3.4 多模态融合搜索

每个时间片段可以拥有以下独立证据：

```text
visual_embedding
caption + caption_embedding
ocr_text + ocr_embedding
transcript + transcript_embedding
FTS exact matches
```

不直接把所有文本拼成一个不可解释的大向量。第一版采用“多路召回 + 时间对齐 + 排名融合”：

1. 查询分别进入视觉向量、描述向量、OCR 向量和转录向量索引。
2. Caption、OCR、Transcript 同时进入 SQLite FTS5，用于姓名、编号、错误码等精确命中。
3. 各模态先独立产生候选，避免不同向量分数范围直接比较。
4. 使用加权 Reciprocal Rank Fusion 合并排名，并对精确文本命中增加有限奖励。
5. 同一视频中重叠或相距不超过配置阈值的证据合并成一个结果。
6. 每个结果公开分数拆解、命中模态和证据文本。

初始权重作为可版本化配置，而不是写死在 UI：

| 模态 | 初始权重 |
| --- | ---: |
| 视觉 | 0.40 |
| 片段描述 | 0.25 |
| 语音转录 | 0.20 |
| OCR | 0.15 |

精确 OCR 或转录查询可能需要不同权重。权重是否动态调整必须通过真实查询集验证，第一版不加入不可解释的查询分类器。

## 4. 数据与索引设计

继续使用现有 Artifact 数据层，不建立旁路数据库。新增三个 Artifact 类型：

```text
scene_caption
ocr
transcript
```

每种分析器独立产生 Analyzer Run 和不可变 Artifact。失败或重跑只影响对应分析器。所有记录继续使用：

```text
media_id
artifact_id
segment_id
start_ms
end_ms
data
metadata
```

建议增加以下索引定义：

- `caption_semantic_current`
- `ocr_semantic_current`
- `transcript_semantic_current`
- `multimodal_current`

文本 Artifact 先持久化原文，再构建语义向量。更换融合策略、文本 embedding 或字段组合时，只重建 Index Version，不重新运行 Caption、OCR 或 Whisper。

为精确搜索增加 SQLite FTS5 投影，至少包含：

```text
media_id
artifact_record_id
modality
start_ms
end_ms
original_text
normalized_text
```

数据库迁移必须向后兼容已有视觉索引。打开旧数据库时自动迁移；迁移失败不得破坏旧数据。

## 5. 本地执行与资源调度

### 5.1 Worker 边界

Rust 负责作业编排、状态、Artifact 提交、搜索和 UI。Python Worker 负责模型推理：

- `caption_worker.py`
- `ocr_worker.py`
- `whisper_worker.py`
- 现有 `qwen_worker.py`

Worker 使用 JSON Lines 协议并长期驻留，避免逐片段加载模型。协议必须包含 `ready`、模型信息、批次结果、耗时和结构化错误。

### 5.2 GPU 调度

第一版采用保守的单 GPU 调度器：

- 同一时刻只允许一个高显存生成模型执行推理。
- 视觉 embedding、Caption、Whisper 和 GPU OCR 通过统一许可控制并发。
- 解码和预处理可以有限度流水并行，但队列必须有上限。
- 每批结束记录 GPU 利用率、显存、CPU 内存、解码时间和推理时间。
- 在真实数据证明安全前，不让多个大模型同时常驻显存。

后续可根据实测把兼容模型并存，但必须以吞吐提升和内存稳定性为依据。

### 5.3 内存保护与恢复

- 帧和音频临时文件采用有界缓存，并在 Artifact 安全提交后清理。
- 每批释放 Python、Torch 和解码器引用；定期执行受控垃圾回收。
- CPU 内存达到 85% 时降低预取和并行度。
- 达到 90% 时停止新批次、提交进度并主动释放 Worker 缓存。
- 达到 95% 时保存进度并执行既定的机器恢复流程；任务通过幂等键和已提交 Artifact 自动续跑。
- 取消、崩溃和重启不得使已完成记录重复或进入搜索两次。

## 6. 产品与接口改动

### 6.1 桌面端

每个视频显示四项独立状态：

```text
视觉  描述  OCR  语音
```

状态至少包括：未开始、处理中、完成、无内容、失败。视频完成任何一种分析后，对应搜索能力立即可用。

搜索结果新增：

- 命中来源徽标。
- Caption、OCR 或转录证据片段。
- OCR 帧和视觉匹配帧。
- 展开的分数拆解。
- 仍然共享现有播放、跳转、放大、打开文件夹和下载片段逻辑。

设置界面新增：

- 启用或关闭各分析器。
- 本地模型选择和语言设置。
- 质量/速度预设。
- 各模型设备、显存和运行状态。

“清除索引”需要区分：仅清除可重建索引、清除某类 Artifact、清除该库所有派生数据。所有选项都不得删除源视频。

### 6.2 CLI 与服务端

计划增加或扩展：

```text
understand-all
understand-caption
understand-ocr
understand-transcript
search --modalities
inspect-understanding
```

HTTP API 增加：

- 每视频、每分析器状态。
- 多模态查询及权重配置。
- 命中证据和分数拆解。
- 分析器的启动、停止、恢复和失败重试。

现有 API 保持兼容；默认搜索可升级为融合搜索，但响应中需要保留当前客户端依赖的字段。

## 7. 实施阶段

### 阶段 A：可行性基准与契约冻结

交付：

- 本地 Caption、OCR、Whisper 各自的最小烟雾测试。
- 模型、版本、显存、速度和输出质量对比。
- 三类 AnalyzerOutput JSON Schema。
- Worker 协议和错误语义。
- 固定的小型测试媒体集及人工标注查询。

通过条件：三个分析器均不调用云服务，可在本机独立处理至少一个真实视频并返回有效时间戳。

### 阶段 B：分析器与 Artifact 持久化

交付：

- Caption、OCR、Whisper Worker。
- Rust 分析器适配器和统一调度器。
- 幂等、取消、恢复、失败隔离和模型来源记录。
- 单视频及多视频 CLI 流程。

通过条件：一个视频可以产生三个独立、可检查、不可变的 Artifact；重跑相同配置不重复推理。

### 阶段 C：文本索引与融合检索

交付：

- 文本 embedding 投影。
- SQLite FTS5 精确搜索。
- 时间对齐、多路候选合并、RRF 排序和分数解释。
- 视觉单模态与融合搜索的回归对比。

通过条件：视觉、Caption、OCR、转录可单独查询，也可在同一请求中融合；未完成模态不会提供候选。

### 阶段 D：桌面端与服务端集成

交付：

- 分析器设置和逐项进度。
- 增量更新的视频卡片和搜索结果。
- 证据文本、命中帧、来源徽标和分数拆解。
- 服务端状态、搜索和恢复接口。

通过条件：任意视频完成一种分析后，UI 无需刷新即可搜索该模态；停止和恢复操作不丢失已提交结果。

### 阶段 E：可靠性、性能与迁移

交付：

- 有界缓存和 GPU 调度。
- 旧数据库自动迁移。
- 删除文件夹、清除索引和清除 Artifact 的正确级联。
- Worker 崩溃、断电式终止、机器重启和断点续跑测试。
- CPU、GPU、显存和内存指标。

通过条件：长时间运行无持续内存增长；重启后任务可恢复；源视频始终不被修改。

### 阶段 F：真实目录 E2E 与现实应用报告

交付：

- 自动化 E2E 结果。
- 人工查询评测结果。
- 性能、准确率、稳定性和 UI 审查。
- 与视觉单模态基线的对比报告。
- 已知限制及下一阶段建议。

## 8. 测试计划

### 8.1 自动化测试

单元测试：

- 时间戳、文本标准化、OCR 去重、转录分段。
- Worker 协议、超时、异常输出和重启。
- RRF、精确匹配奖励、时间合并和分数拆解。
- 数据库迁移、幂等和不可变约束。

集成测试：

- 三个真实 Worker 各自生成 Artifact。
- Artifact 构建多个索引而不重新推理。
- 部分完成时搜索只使用已完成模态。
- 停止、恢复、清除和文件夹移除。
- 服务端 API 与桌面端使用相同搜索逻辑。

桌面 E2E：

- 添加多个文件夹并折叠列表。
- 启动后按钮切换为停止。
- 每个视频完成分析后状态立即变化。
- 索引未全部完成时持续搜索。
- 搜索结果显示正确证据帧和文本。
- 详情、播放、拖动、前后跳转、放大、打开文件夹和下载片段。
- 大型列表只对可见项目加载缩略图和证据图。

### 8.2 真实数据测试

最终在 `C:\迅雷下载` 上执行只读测试：

1. 首先只扫描元数据，记录文件数、格式、总时长和磁盘规模。
2. 从不同长度、分辨率和内容中抽取代表性子集，覆盖：
   - 有人声与无声视频。
   - 中文、英文和混合语言。
   - 屏幕录制、字幕、路牌和自然场景。
   - 低清晰度、快速运动、长视频和短视频。
3. 子集通过后执行全目录长时间稳定性测试。
4. 所有数据库、缓存、缩略图和临时文件写入项目 `.tools` 下的隔离目录。
5. 不删除、重命名、移动或写入源视频。

人工建立至少 30 条现实查询，分为：

- 纯视觉语义。
- 片段描述。
- OCR 精确文字。
- 语音内容。
- 两种或以上模态组合。
- 不应命中的负例。

### 8.3 质量指标

| 领域 | 指标 |
| --- | --- |
| 搜索质量 | Recall@5、Recall@10、MRR、空结果率 |
| OCR | 字符错误率、关键词命中率、重复率 |
| 转录 | 词错误率或字错误率、时间戳偏差 |
| Caption | 人工相关性、事实错误率、遗漏率 |
| 融合收益 | 相对视觉单模态的 Recall/MRR 改善 |
| 性能 | 每小时视频处理时间、各阶段耗时、搜索 P50/P95 |
| 资源 | GPU 利用率、显存峰值、CPU 峰值、内存峰值与增长趋势 |
| 稳定性 | 失败率、恢复成功率、重复记录数、长跑内存斜率 |
| UI | 首次反馈时间、逐视频更新时间、交互错误数 |

质量门槛在阶段 A 用真实样本校准后冻结，避免提前设定脱离语料的数字。至少必须证明融合检索相较现有视觉检索有可重复的正向收益，且不会明显损害纯视觉查询。

## 9. 现实应用报告

最终报告写入 `REPORT_MULTIMODAL_UNDERSTANDING.md`，内容包括：

1. 本机硬件、软件、模型和配置。
2. 测试语料的类型、规模、时长和语言分布，不暴露私人内容或文件名。
3. Caption、OCR、Whisper、文本 embedding 和视觉 embedding 的独立性能。
4. 端到端索引吞吐、搜索延迟、GPU/CPU/内存曲线。
5. 视觉单模态与融合检索的查询级对比。
6. 成功案例、失败案例和失败原因分类。
7. UI 操作路径和人工体验审查。
8. 取消、恢复、重启、清除索引和文件夹移除的可靠性结果。
9. 隐私与本地运行验证。
10. 当前限制、推荐默认配置和下一阶段优先级。

报告中的结论必须来自实际运行数据；示例结果、模拟结果和真实结果要明确区分。

## 10. 风险与控制

| 风险 | 控制措施 |
| --- | --- |
| 多模型抢占显存 | 第一版串行 GPU 许可；记录峰值后再开放并发 |
| CPU 解码仍是瓶颈 | Caption/OCR 复用代表帧；NVDEC 优先；限制预取 |
| Caption 幻觉 | 约束 JSON、保留原始证据帧、不把生成内容当作确定事实 |
| OCR 重复和噪声 | 相似帧跳过、时间/空间去重、置信度阈值 |
| Whisper 长视频内存增长 | 流式音频、VAD、分段提交、有界队列 |
| 不同模态分数不可比 | 使用排名融合并公开分数拆解，不直接混合原始余弦分数 |
| 旧索引不兼容 | 版本化迁移、备份、回滚测试和旧 API 回归 |
| 部分结果污染搜索 | 仅发布已完成并验证的 Artifact/Index 能力 |
| 机器重启造成重复处理 | 幂等键、事务提交、恢复清单和已完成记录检查 |

## 11. 完成定义

本项目只有同时满足以下条件才算完成：

- Caption、OCR、Whisper 均在本机资源上真实运行，不依赖云服务。
- 每种输出都有时间戳、模型来源、配置和可复用 Artifact。
- 现有视觉搜索、图片搜索、播放和片段下载没有回归。
- 多模态融合搜索支持自然语言、精确文字和语音内容查询。
- 搜索结果显示命中来源、证据和分数拆解。
- 部分索引、停止、恢复和机器重启场景均可用。
- 桌面端和服务端共享同一套核心检索逻辑。
- 自动化测试通过，并完成 `C:\迅雷下载` 的只读真实 E2E。
- 完成基于真实数据的应用报告，明确收益、性能和局限。
- 代码、测试、文档和报告均不包含私人视频内容、外部演示地址或凭据。

## 12. 评审决策点

开始实现前需要确认以下设计方向：

1. 第一版使用固定 30 秒 Caption 窗口，镜头切分留作后续优化。
2. 搜索融合采用可解释的 RRF，而不是一次性训练融合模型。
3. Whisper 模型根据本机真实中英文测试选择，不预先锁死最大模型。
4. GPU 第一版保守串行调度，稳定后再提高并发。
5. 原始分析 Artifact 长期保留；索引可单独清除和重建。
