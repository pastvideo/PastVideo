# PastVideo 多模态理解首版：现实 E2E 报告

> 日期：2026-08-02
> 当前产品状态：真实试用反馈表明 Caption、OCR、Whisper 的结果质量尚未达到桌面产品要求。PastVideo Desktop 已撤下相关入口和证据展示，桌面搜索只使用视觉索引；实验实现仅保留在 CLI/服务端供后续改进与评测。

以下内容是该实验版本的历史工程验证记录，不代表当前桌面版已发布能力。

## 1. 本次交付范围

- 本地 Qwen3-VL-4B-Instruct 生成 30 秒片段的结构化场景描述。
- RapidOCR PP-OCRv6 读取抽样帧中的屏幕文字，并保留置信度、帧时间和文字框。
- faster-whisper `small` 生成带片段和词级时间戳的语音转录，CUDA 不可用时回退 CPU。
- 三种文本 Artifact 与现有视觉向量共同进入 SQLite 持久化索引。
- 文本语义检索与 FTS5 精确检索使用加权 RRF 融合；未完成视觉索引的视频不会成为候选。
- 桌面端支持启动、停止和恢复理解任务，并显示当前分析阶段。
- 搜索卡片和详情显示命中来源、对应文字证据和正确的匹配画面。
- CLI、无 GUI 服务端和桌面端共用相同的融合检索逻辑。

## 2. 测试环境

| 项目 | 实际环境 |
| --- | --- |
| GPU | NVIDIA GeForce RTX 4090 D，24 GB |
| CPU | AMD Ryzen 7 9700X |
| 系统内存 | 61.7 GB |
| Caption | Qwen3-VL-4B-Instruct，BF16 CUDA |
| OCR | RapidOCR 3.9.2 / PP-OCRv6，CPU |
| 语音 | faster-whisper 1.2.1，`small`，CUDA |
| 文本/视觉向量 | Qwen3-VL-Embedding-2B，CUDA |
| 持久化 | SQLite WAL + FTS5 |

长时间实测中，系统内存使用率约 48%–55%，没有接近 95% 的自动重启阈值；Caption 稳态采样时 GPU 利用率约 64%–66%，总显存占用约 15.8 GB。Caption 完成并释放模型后，显存回落到约 6.9 GB。

## 3. 现实素材

指定目录包含 10 个受支持的 MP4 文件，共约 4.35 小时、3.77 GB；单个视频约 24.9–28.3 分钟。MTS、M2TS 和其他非视频文件没有进入候选。

完整质量与性能测试使用其中最短的一集：

- 时长：约 24.9 分钟（约 1,492 秒）
- Caption/OCR 窗口：30 秒，5 秒重叠
- 场景描述记录：60
- OCR 记录：60，其中 57 条含可搜索文字，3 条为空
- Whisper 语音记录：351
- 最终可搜索文本记录：468

另用 9.03 秒真实手机视频验证桌面展示、场景搜索、英文语音搜索、播放和放大播放器。

## 4. 性能结果

### 4.1 短视频冷启动

9.03 秒视频在新的隔离索引中完成视觉、Caption、OCR、Whisper 和文本向量发布：

| 指标 | 结果 |
| --- | ---: |
| 三个本地分析器 | 14.36 秒 |
| 完整冷启动墙钟时间 | 32.8 秒 |
| 第二次相同请求 | 0.9 秒 |
| 第二次新增记录 | 0 |
| 第二次复用分析器 | 3/3 |

短视频主要受模型冷启动支配，不能代表长视频稳态吞吐。

### 4.2 24.9 分钟整集

| 阶段 | 实测时间 | 相对实时速度 |
| --- | ---: | ---: |
| Caption + OCR 分析 | 155.79 秒 | 9.6× |
| Whisper `small` 分析 | 23.44 秒 | 63.7× |
| 两次隔离发布的墙钟合计 | 209.2 秒 | 7.1× |

按本次保守墙钟值计算，新增理解能力约需要每视频小时 8.4 分钟。此前同机视觉索引基线约为每视频小时 2.13 分钟，因此完整多模态首版约为纯视觉的 4 倍墙钟成本。指定 4.35 小时目录的线性估算约为 37–45 分钟，模型首次下载不计入其中。

新的正式流程只加载一次文本向量模型，并对三个分析器分别提交；因此全流程通常会略快于上表中为了故障隔离而执行的两次发布。

## 5. 质量抽查

### 场景描述

五个分散时间点的人工抽查均与画面主体一致，包括暗室人物、工业设施、持枪对峙和片尾字幕。查询 `holding guns in a dark industrial setting` 的首位结果为 15:00–15:30，返回场景描述证据，符合画面内容。

### Whisper

模型自动识别日语并生成 351 个带时间戳片段。使用视频中的日语原句查询时，首位结果准确落在 2:26–2:28，并显示对应转录证据。

### OCR

片尾多语言制作人员名单识别效果好，精确英文短语查询最终准确落在 23:45–24:15。低清、运动、艺术字体画面仍可能出现乱码；9 秒手机样本中的 OCR 即属于低价值噪声。首版通过置信度阈值、相似帧跳过和空文本过滤控制噪声，但还没有达到“所有画面文字都可靠”的程度。

### 融合排序

现实测试最初发现精确 OCR 的权重 0.15 低于视觉权重 0.40，导致存在于索引中的精确短语未进入前三。修复后，精确 OCR/转录权重提升为 0.75；精确短语成为首位，同时自然语言场景查询仍由视觉和 Caption 协同排序。该行为已有自动回归测试。

## 6. 原生桌面 UI E2E

在当前 Windows 原生构建中实际完成以下操作：

1. 加载 2 个目录和 22 个视频，检查可折叠目录列表与虚拟化视频网格。
2. 搜索保龄球场景，首位显示真实匹配缩略图。
3. 发布 Caption 后重新搜索，卡片和详情显示 `SCENE DESCRIPTION` 及场景证据。
4. 搜索 `Thank you`，首位显示 `SPEECH TRANSCRIPT`、0:04–0:05 和转录证据。
5. 在详情中播放、暂停并打开大播放器。
6. 确认大播放器从匹配点启动，但时间轴覆盖完整 0:00–0:09 视频；前后 10 秒、停止、播放和拖动条均可用。
7. 确认搜索在理解任务之外始终可用，现有视觉索引不因某个文字模态缺失而失效。

UI 审查没有发现遮挡、溢出或不可点击控件。证据文字在卡片中单行截断，在右侧详情中完整显示；视觉层级清晰。

## 7. 测试覆盖

- 51 个 Rust 单元测试全部通过。
- 架构、桌面目录到搜索、部分索引时搜索、索引停止与恢复、视频裁剪和 provider 合约 E2E 全部通过。
- Rust 到 Python 的真实进程协议 E2E 逐一运行 Caption、OCR、Transcript mock 作业并通过。
- 融合检索 E2E 覆盖 Artifact 持久化、文本向量、FTS5、精确文本优先、未视觉索引视频排除、幂等重跑、进程重启和清空索引。
- 真实 GPU 短视频全链路通过，第二次执行 3/3 分析器复用且新增记录为 0。
- 指定现实目录中的完整 24.9 分钟视频通过 Caption、OCR、Whisper 和三类查询验证。

## 8. 测试发现并已修复的问题

1. Windows GBK 管道无法输出转录中的部分 Unicode 字符。机器协议现使用 ASCII 安全的 JSON Unicode 转义，并用混合 Unicode 回归测试验证。
2. 三个分析器原先在一次进程结果中整体提交，末阶段失败会浪费前面结果。现按分析器使用独立幂等键，完成一个即持久化；重跑只补缺失项。
3. mock worker 原先忽略单分析器选择，拆分后会重复产生三类结果。现严格遵循 `skip` 开关。
4. 精确 OCR 权重不足。现保证精确屏幕文字或原句优先于纯视觉近似结果。
5. 离线模式下未缓存 Whisper `small` 会失败。安装脚本现在默认预下载 Caption 和 Whisper 默认模型；也可显式跳过预下载，并在首次在线使用时缓存。

## 9. 仍需继续优化

- Caption 是主要新增成本。下一步应让 Python worker 跨视频常驻，避免每个视频重新加载 4B 模型。
- Caption 和 OCR 目前分别读取抽样帧；应复用同一帧缓存，并继续评估 768 降到 512 像素及 4 帧降到 3 帧的质量/速度曲线。
- 桌面端已显示当前分析器阶段，但长视频还应增加片段级进度和预计剩余时间。
- OCR 需要更强的字幕区域检测、跨帧合并和乱码过滤；低质量 OCR 不应获得与高置信文本相同的融合贡献。
- 当前固定 30 秒 Caption 窗口在快速剪辑内容中可能过粗；镜头切分应作为下一版实验，而不是直接替换稳定路径。
- 需要建立更大的人工标注查询集，分别报告 Caption 事实正确率、OCR 关键词命中率、Whisper 字错率和融合 Recall@K。

## 10. 发布判断

首版已经适合用于个人本地视频库试用和继续收集真实反馈：数据全程本地、结果可追溯、失败可恢复、搜索可在部分完成时工作。它还不适合宣称为高精度档案 OCR 或零幻觉视频理解系统。对于当前机器和约 4.35 小时的目录，性能可接受；下一阶段最值得投入的是常驻 Caption worker、共享抽帧与片段级进度。
