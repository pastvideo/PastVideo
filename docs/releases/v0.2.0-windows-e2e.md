# PastVideo v0.2.0 Windows release E2E report

Date: 2026-08-02

## Verdict

The released Windows archive completed the full path from download to real GPU
indexing, search, playback, segment export, stop/resume, and application restart.
It is usable without a system Python, CUDA Toolkit, or separate FFmpeg install.

The built-in and external download paths are ready for normal use. Users can
download the model or the three runtime ZIP files in PastVideo, copy direct
download links into another download manager, or import files they already
downloaded.

The main archive downloaded in 10.8 seconds and extracted in 1.9 seconds on this
machine. The built-in model transfer completed in about 4.5 minutes under the
network conditions during the test. Downloaded files were retained across app
restarts.

## Download progress behavior

Both runtime and model downloads show a determinate progress bar with downloaded
and total GiB. Runtime progress is aggregated across all three archives and shows
the current filename plus `1/3`, `2/3`, or `3/3`. Checking, downloading,
verifying, copying, and installing are visible states, so the UI no longer has a
silent preflight interval. A resumed download starts from its existing byte count.
Buttons that could conflict with an active transfer remain disabled until the
operation finishes.

## Real usage results

- PastVideo found exactly the 10 supported videos in the real folder.
- The app used the bundled local runtime and the NVIDIA GPU. PyTorch reported
  CUDA available and identified the RTX 4090 D.
- Observed VRAM use was about 10.6 GiB. System memory stayed near 57%, well below
  the 95% restart threshold.
- Active visual indexing took roughly 9–10 minutes for 4.34 hours of video,
  excluding downloads and the intentional stop interval. The pipeline remained
  CPU-limited and GPU utilization was bursty.
- Completed videos moved from `Unsorted` to `Entertainment` immediately. The
  counts updated while later videos were still indexing.
- Search remained enabled during indexing. Results contained only completed
  indexed videos at the time each query snapshot was created.
- Stopping indexing kept completed work. Restarting resumed the remaining three
  videos and finished at 10/10 videos and 630 moments.
- A Chinese semantic query returned clip-specific thumbnails from the real
  library, including results from the tenth video after the full index completed.
- Detail playback, pause, stop, enlarged playback, ±10-second controls, and
  progress-bar seeking all worked.
- Segment export produced a playable 30.05-second MP4.
- After a final restart, PastVideo restored all 10 classifications and all 630
  moments. Running index again returned zero new moments without downloading or
  rebuilding anything.

## Follow-up regression on the updated package

- A clean, isolated AI directory imported all three downloaded runtime ZIP files
  through the native multi-file picker. The installed portable runtime contained
  PyTorch 2.11.0 with CUDA 12.8, detected the RTX 4090 D, and reported CUDA ready.
- A separate isolated model directory started with a real 64 MiB partial file.
  PastVideo displayed the resumed byte count immediately, downloaded to 208.71
  MiB, and retained the partial file after a normal application close.
- Readiness notices now distinguish a completed component install from a fully
  ready local AI setup. `Local AI is ready` appears only when both the runtime and
  model are available.

## Automated regression

`cargo test --locked` passed with 56 unit tests plus the native and integration
suites, including folder-to-search E2E, partial-index
search, stop/resume, matched clip thumbnail and export, provider contracts, model
distribution metadata, multimodal storage, and `.mts`/`.m2ts` rejection. Web lint
and strict Clippy checks also passed. The existing demo processes remained running
after the test.
